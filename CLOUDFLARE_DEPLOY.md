# Cloudflare Workers Deployment

This application is a full-stack Next.js app with route handlers and server-side Supabase access. Deploy it to **Cloudflare Workers**, not a static Cloudflare Pages export.

## Execution owner

Hermes VPS AWS, because the Cloudflare, Supabase, Meta, and deployment credentials already exist there.

## Preflight

```bash
git fetch --all --prune
git checkout fix/mobile-ui-cloudflare
git pull
npm ci
npm run typecheck
npm run lint
npm test
npm run build
```

All checks must pass before Cloudflare deployment.

## Configure existing project automatically

Use Wrangler 4.68.0 or newer:

```bash
npx wrangler@latest setup
```

Wrangler should detect Next.js and configure the `@opennextjs/cloudflare` adapter. Review generated files before committing them.

If automatic setup is unavailable, follow the current Cloudflare Next.js Workers/OpenNext documentation and do not convert the application to a static export.

## Secrets

Copy production environment variable names from the existing runtime, but never print values in logs or commit them.

At minimum verify:

- NEXT_PUBLIC_SUPABASE_URL
- SUPABASE_SERVICE_ROLE_KEY
- DB_URL
- HERMES_OWNER_USER_ID
- HERMES_API_KEY
- CRON_SECRET
- TOKEN_ENCRYPTION_KEY
- META_APP_ID
- META_APP_SECRET
- META_GRAPH_VERSION
- BIRRULABS_API_KEY or AI_API_KEY
- NEXTAUTH_URL
- NEXTAUTH_SECRET

Set secrets using Wrangler secret commands or the Cloudflare dashboard. `NEXTAUTH_URL` must be changed to the final Cloudflare production domain.

## Deploy

Run the deploy script generated by Wrangler/OpenNext. If scripts are not generated, stop and complete adapter setup first.

## Required smoke tests

- `/` redirects to `/dashboard`
- `/dashboard` renders correctly at 360, 390, 768, 1024, and desktop widths
- mobile sidebar is closed by default
- hamburger opens the drawer
- backdrop and close button dismiss it
- `/dashboard/accounts`
- `/dashboard/posts`
- `/dashboard/analytics`
- `/api/v1/health` returns HTTP 200 and `database: ok`
- dashboard stats return real values
- no secrets appear in HTML, JS bundles, or logs

## DNS cutover

Do not remove the working Vercel deployment during validation. First deploy to a `workers.dev` or preview domain, run all smoke tests, then attach the intended custom domain. Keep Vercel as rollback until Cloudflare passes production verification.
